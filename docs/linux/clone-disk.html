Clone Disk

Copy a whole disk to another disk

Clone one whole disk onto another with ddrescue. Everything on the destination disk is overwritten, and the destination must be at least as large as the source. If you only need the files, or the destination is smaller, use Image a Failing Drive instead.

Optional first step: shrink the partition. If the destination is smaller than the source disk, shrink the Windows partition first so the data fits, then follow Clone to a smaller disk at the bottom of this page instead of step 3. In GParted, right-click the partition, choose Resize/Move, reduce the size and apply. Only do this on a healthy source: resizing writes to the disk and can lose data on a failing one, and on a failing disk you should use Image a Failing Drive or copy the files instead. Windows partitions that were hibernated or shut down with Fast Startup, or are BitLocker encrypted, cannot be resized until that is cleared.

install and run GParted 
sudo pacman -Sy gparted
sudo gparted

1. Identify the source (the disk to copy from) and the destination (the disk to overwrite). Check the size and model of each carefully. Getting them the wrong way round destroys the data you are trying to save.

identify drives 
lsblk

2. Install ddrescue if the live ISO does not have it. The Arch/CachyOS package is named ddrescue.

install 
sudo pacman -Sy ddrescue

3. Clone. The source comes first, then the destination, then a log (map) file. Replace /dev/sda (source) and /dev/sdb (destination) with your drives. -d reads the source directly, -f allows writing to a disk, and -r1 retries bad areas once. Safe to stop and re-run with the same command; the log remembers progress.

clone 
sudo ddrescue -d -f -r1 /dev/sda /dev/sdb clone.log

The log file is written to the current folder. On a live ISO that is in RAM and disappears on reboot, so for a long job point it at a drive that stays connected (for example /mnt/target/clone.log) so you can resume after a restart. If the source drops out part way through, power-cycle it and re-run the same command.

Clone to a smaller disk

For example 1 TB mechanical to 500 GB NVMe

A plain clone fails when the destination is smaller than the source, because ddrescue tries to copy the whole source disk. The fix is to shrink the Windows partition so everything sits near the start of the disk, then copy only that part. Use this for a healthy source (a disk upgrade); on a failing disk use Image a Failing Drive or copy the files. Keep the original disk untouched until the new one boots. In the commands, /dev/sda is the source and /dev/sdb is the destination (an NVMe in a USB dock appears as a sdX disk); check with lsblk.

A1. Shrink the Windows partition in GParted (see the optional step at the top) so the used data fits with room to spare: for 90 GB used, 150 to 200 GB is plenty. If a Recovery partition sits after the Windows partition, move it left as well, so that no partition ends beyond the size of the destination disk. Apply the changes.

A2. Work out where the last partition ends, in bytes. This prints a number such as 96600000001.

end of last partition 
END=$(sudo parted -m /dev/sda unit B print | awk -F: 'NR>2{gsub("B","",$3); if($3+0>m)m=$3+0} END{printf "%d", m+1}')
echo "$END"

A3. Clone only that part of the disk. -s limits how much is copied; without it ddrescue would try to fill the whole 500 GB destination from the 1 TB source. Put the log on a drive that stays connected if you can.

clone first part 
sudo ddrescue -f -d -s "$END" /dev/sda /dev/sdb clone.log

A4. GPT disks only: the backup copy of the partition table is stored at the end of the source disk and is missing on the destination. Move it to the end of the new disk, and check the result. (Not needed for old MBR disks. parted may offer to fix this itself.)

fix GPT 
sudo pacman -Sy gptfdisk
sudo sgdisk -e /dev/sdb
sudo parted /dev/sdb print

A5. Optional: in GParted, grow the Windows partition on the new disk to use the rest of the space, then fit the new disk in the PC and boot from it.
