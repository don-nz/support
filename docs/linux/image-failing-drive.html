Image a Failing Drive

Make a rescue image with ddrescue

For a drive that is really failing, copying files can stress it and stall on bad sectors. ddrescue makes a full image instead, reading the good areas first and recording the bad ones in a map file so it can stop and resume. Work from the image afterwards, not the dying drive. The image needs a different, healthy drive with at least as much free space as the source.

1. Identify the failing drive (source) and the drive to hold the image. Getting these the wrong way round overwrites data.

identify drives 
lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINTS,MODEL

2. Install ddrescue if the live ISO does not have it (the package is named ddrescue).

install 
sudo pacman -S ddrescue

3. Mount the healthy drive that will hold the image.

mount image drive 
sudo mkdir -p /mnt/target
sudo mount -t ntfs-3g -o remove_hiberfile /dev/nvme0n1p3 /mnt/target

4. First pass: copy the easy areas quickly. Replace /dev/sda with the failing drive (the source goes first, the image second). The image file is created at the drive's full size as a sparse file (it takes no space until written), so the partition table is readable even while the image is partly filled. -S skips writing blocks of zeros, which is what saves space on the target; -f lets ddrescue write into the existing file.

pass 1 
IMG=/mnt/target/rescue.img
MAP=/mnt/target/rescue.map
sudo truncate -s "$(sudo blockdev --getsize64 /dev/sda)" "$IMG"
sudo ddrescue -f -d -n -S /dev/sda "$IMG" "$MAP"

5. Second pass: go back over the bad areas, retrying up to 3 times. Safe to stop and re-run; the map file remembers progress.

pass 2 
sudo ddrescue -f -d -r3 -S /dev/sda "$IMG" "$MAP"

6. Attach the image as a read-only loop device. lsblk shows its partitions (/dev/loop0p1, /dev/loop0p2 and so on); find the large NTFS Windows one. The first partitions are often a small EFI and reserved partition, so it is not always p2.

attach image 
loopdev=$(sudo losetup -r -fP --show "$IMG")
lsblk -f "$loopdev"

7. Mount the Windows partition from the image read-only (replace p2 with the right partition), then use Copy Windows Folders to copy the files. If the partition is BitLocker encrypted, unlock it first as on the BitLocker Drives page, using the loop partition.

mount source 
sudo mkdir -p /mnt/source
sudo mount -t ntfs3 -o ro "${loopdev}p2" /mnt/source

8. When finished, unmount and detach.

detach 
sudo umount /mnt/source
sudo losetup -d "$loopdev"

Smaller image

Windows partition only, sparse

The steps above image the whole drive, so the image can be as big as the drive (sparse writes only help where unused sectors are zeros). For a smaller file, image only the Windows partition (the big NTFS one, e.g. /dev/sda2, not /dev/sda) and use -S (sparse) so empty blocks take no space on the target. Everything else about the process is the same. The target drive must be a filesystem that supports sparse files (ntfs-3g, ext4 and others do). The image will still be as large as the data actually on the partition, so make sure there is room for it.

A1. First pass on the partition. Use the partition name from lsblk in step 1, not the whole drive.

pass 1 (partition, sparse) 
sudo ddrescue -f -n -S /dev/sda2 /mnt/target/failing-part.img /mnt/target/failing-part.map

A2. Retry pass, as before.

pass 2 (partition, sparse) 
sudo ddrescue -f -d -r3 -S /dev/sda2 /mnt/target/failing-part.img /mnt/target/failing-part.map

A3. Attach the image read-only. It is a single partition with no partition table, so no -P and no p2: mount /dev/loop0 itself. (If the partition is BitLocker encrypted, unlock /dev/loop0 with the BitLocker Drives steps first.)

attach and mount 
sudo losetup -r -f --show /mnt/target/failing-part.img
sudo mkdir -p /mnt/source
sudo mount -t ntfs3 -o ro /dev/loop0 /mnt/source

A4. Copy the files with Copy Windows Folders, then unmount and detach.

detach 
sudo umount /mnt/source
sudo losetup -d /dev/loop0

Not enough space?

When the target is smaller than the drive

A plain ddrescue image is as big as the drive being imaged (a 2 TB drive needs 2 TB free), even if only 400 GB is used. -S sparse writes help only where unused sectors are all zeros; deleted files and old data keep the image bigger, up to the full size.

Check how much room the target has, and (during or after a sparse image) how much space the image really uses compared with its apparent size.

check space 
df -h /mnt/target
ls -lh /mnt/target/failing-part.img   # apparent size
du -h /mnt/target/failing-part.img    # space actually used

Option 1: skip the image and copy the files. If the drive has only a few errors, Copy Windows Folders needs just the size of the folders you choose. Step 5 on that page shows each folder's size before you commit.

Option 2: image only the used NTFS data. ntfsclone --rescue copies only the allocated clusters of an NTFS partition and carries on past read errors, so the image is about the size of the used data. It cannot image anything except NTFS, and the partition must be unmounted. Replace /dev/sda2 with the Windows partition. If it refuses or reports problems, fall back to option 1.

ntfsclone rescue image 
sudo pacman -Sy --needed ntfs-3g
sudo umount /mnt/source
sudo ntfsclone --rescue -O /mnt/target/failing-part.img /dev/sda2

Then attach and mount it the same way as the smaller image above (losetup -r -f --show, then mount /dev/loop0 read-only) and copy the files from it.

Option 3: borrow a bigger disk. For important data on a dying drive, a full ddrescue image on a drive at least as large as the source is the safest route.

If the drive disconnects part way through, power-cycle it (unplug and replug, or reboot) and re-run the same command. Do not run repair tools such as chkdsk on a failing drive before the image is made.
