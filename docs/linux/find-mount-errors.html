Find Mount Errors

Why a drive will not mount

When a drive will not mount, the reason is in the kernel log. dmesg shows it; run these from a terminal on the live ISO.

Kernel errors and warnings, with readable timestamps.

errors 
sudo dmesg -T --level=err,warn

Follow the log live. Leave this running in one terminal, then plug the drive in or mount it from another, and the messages appear as they happen.

live 
sudo dmesg -w

Only drive-related lines (SATA, disks, NVMe, NTFS).

drive lines 
sudo dmesg -T | grep -iE 'ata[0-9]|sd[a-z]|nvme|ntfs'

The same kernel messages via the journal for this boot, and the desktop auto-mount attempts.

journal 
sudo journalctl -k -p warning -b
sudo journalctl -b | grep -iE 'udisks|mount'

Save the log to a file instead of photographing the screen. Put it on a healthy drive or the Ventoy USB.

save log 
sudo dmesg -T > ~/dmesg.txt

What the messages mean

  • ata2.00: failed command: READ FPDMA QUEUED with error: { UNC }: the drive could not read some sectors (uncorrectable). The disk surface is damaged. Stop mounting it and image it with Image a Failing Drive. The ata2 number is the SATA port, .00 the drive on it; the model name is printed earlier in the log.
  • link down on a port with no drive is normal. On a port that should have a drive, check the cable and power.
  • hard resetting link, SError or ICRC errors: often a bad cable, dock or power rather than the platters. Try another cable or port before assuming the drive is dead.
  • exception Emask followed by EH complete: the kernel hit a drive error and recovered. Repeated lines mean it keeps happening.
  • NTFS messages about a dirty or hibernated volume: Windows did not shut down cleanly or hibernated. See Copy Windows Folders (the remove_hiberfile option) or mount read-only.
  • A BitLocker filesystem type in lsblk -f means the partition is encrypted and will not mount until unlocked. See BitLocker Drives.
