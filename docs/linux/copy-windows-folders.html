Copy Windows Folders

Rescue files from a failing Windows drive

Run from a Linux live ISO (for example CachyOS). If the drive will not mount because it is encrypted, see BitLocker Drives. If the drive is badly failing, make an image first with Image a Failing Drive.

1. List the drives and find the failing source and the target. Note the partition names (e.g. sda2, nvme0n1p3) and use them in the steps below.

identify drives 
lsblk -o NAME,FSTYPE,SIZE,MOUNTPOINTS,MODEL

2. Mount the failing Windows drive read-only as the source.

mount source 
sudo mkdir -p /mnt/source
sudo mount -t ntfs3 -o ro /dev/sda2 /mnt/source

3. Mount the target drive. remove_hiberfile lets NTFS mount read-write if Windows left it hibernated.

mount target 
sudo mkdir -p /mnt/target
sudo mount -t ntfs-3g -o remove_hiberfile /dev/nvme0n1p3 /mnt/target

4. List the user profiles on the drive, then set the variables. Put the profile name in SRC and edit FOLDERS to the base folders you want. These are bash commands (the CachyOS live terminal is bash). If the user has OneDrive, Desktop and Documents may be inside OneDrive as well, so check that folder too.

set variables 
ls /mnt/source/Users

SRC="/mnt/source/Users/Name"
DST="/mnt/target/Recovered/Name"
FOLDERS=(Desktop Documents Downloads Pictures Music Videos)

ls "$SRC"

5. Show the file count and total size of each base folder. This reads directory information only, not file contents, but on a failing drive it can still be slow or print errors.

files and size per folder 
for f in "${FOLDERS[@]}"; do
  n=$(sudo find "$SRC/$f" -type f 2>/dev/null | wc -l)
  s=$(sudo du -sh "$SRC/$f" 2>/dev/null | cut -f1)
  printf '%-12s %8s files  %s\n' "$f" "$n" "$s"
done

6. Count the files by type (extension) in one base folder, most common first. Change BASE to the folder you want to look at.

files by type 
BASE="$SRC/Pictures"
sudo find "$BASE" -type f 2>/dev/null \
  | sed -E 's/.*\.([^./]+)$/\1/;t;s/.*/(none)/' \
  | tr 'A-Z' 'a-z' | sort | uniq -c | sort -rn

7. Copy the base folders with their subfolders and files. It asks y/N for each folder in FOLDERS, so you choose as you go; delete the read and continue lines to copy them all without asking. --ignore-errors and --timeout=10 stop bad sectors from stalling the copy. Re-run it to resume.

copy chosen folders 
for f in "${FOLDERS[@]}"; do
  read -r -p "Copy $f? [y/N] " ans
  [[ $ans == [yY]* ]] || continue
  sudo mkdir -p "$DST/$f"
  sudo rsync -avP --ignore-errors --timeout=10 "$SRC/$f/" "$DST/$f/"
done

8. Check how much was copied, per folder.

check size 
du -sh "$DST"/*/
