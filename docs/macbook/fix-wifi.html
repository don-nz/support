Fix Wi-Fi

MacBook Wi-Fi will not connect

For a MacBook whose Wi-Fi will not connect or has disappeared. Open Terminal first: press Cmd + Space for Spotlight, type Terminal and press Enter.

1. List the network hardware. Look for a Wi-Fi port with device en0. If there is no Wi-Fi entry, do step 2.

list ports 
networksetup -listallhardwareports

2. If the Wi-Fi service is missing, recreate it.

create Wi-Fi service 
sudo networksetup -createnetworkservice Wi-Fi en0

3. Check the Wi-Fi hardware, whether it has an IP address, and whether the internet and DNS work. No output from ipconfig means no address. If the first ping works and the second does not, it is a DNS problem.

check status 
system_profiler SPAirPortDataType
ipconfig getifaddr en0
ping -c 3 1.1.1.1
ping -c 3 apple.com

4. If it is still not working, delete the saved network configuration files and reboot. macOS rebuilds them on startup. This forgets all saved Wi-Fi networks and may reset other network settings (VPNs, Ethernet, custom DNS), so note any that matter first.

reset network config 
sudo rm -f /Library/Preferences/SystemConfiguration/com.apple.airport.preferences.plist
sudo rm -f /Library/Preferences/SystemConfiguration/com.apple.network.eapolclient.configuration.plist
sudo rm -f /Library/Preferences/SystemConfiguration/com.apple.wifi.message-tracer.plist
sudo rm -f /Library/Preferences/SystemConfiguration/NetworkInterfaces.plist
sudo rm -f /Library/Preferences/SystemConfiguration/preferences.plist

5. For a network that still will not connect, such as university (802.1X / enterprise) Wi-Fi, try connecting and then read the last 5 minutes of the Wi-Fi and enterprise-authentication log. eapolclient is the 802.1X client, so errors from it point to the login, certificate or profile.

check log 
log show --predicate 'process == "eapolclient" or process == "airportd"' --last 5m

Result so far

After steps 1 to 4 and a reboot, a MacBook connected to phone hotspots and home Wi-Fi again. University Wi-Fi still had problems, so the cause there is likely separate (the enterprise login, certificate or profile). See below.

University Wi-Fi (ACU, acuwifi)

Steps tried so far. The client has not yet reported back on the result. The Keychain entries were found under ACUCA.

  1. Remove the saved network. If acuwifi is not in the Known Networks list, go to System Settings > Wi-Fi, scroll to the bottom and click Advanced.... Find acuwifi (or any ACU entry), click the three dots (...) next to it, choose Remove From List and click Done.
  2. Remove the saved credentials and certificate from Keychain Access. Open Keychain Access (Cmd + Space, then search for it). Select System (or Local Items) in the sidebar and search for acuwifi (searching for the server name may find nothing). Delete any 802.1X, network password or certificate entries for it. Entries named ACUCA were also found; check them as well.
  3. Force a fresh login. Turn Wi-Fi off, wait 5 seconds, turn it on, and pick acuwifi from the scan list. When prompted, enter the student ID only as the username (for example s00123456, without @acu.edu.au) and the account password. When the certificate pop-up for mqnvpuise04.acu.edu.au appears, click Continue and enter the Mac's administrator password or Touch ID to accept the certificate.

If it still fails, run the step 5 log command straight after a connection attempt and look at the eapolclient errors, or ask the university IT help desk for their Wi-Fi setup profile.
